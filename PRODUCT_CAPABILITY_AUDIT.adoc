= Product Capability Audit: Pricing
:revdate: 2026-09-21

== Boundary verdict

Pricing now implements reusable price definitions and deterministic price selection through immutable contracts and a selection service. It does not own promotion, tax calculation, currency conversion, payment execution, or order totals.

== Capability matrix

[cols="3,1,4",options="header"]
|===
|Capability |Status |Audit
|Price/PriceSet identity |IMPLEMENTED |Immutable PriceDefinitionDTO and PriceSetDTO enforce identity and external priceable-reference invariants.
|Price lists |IMPLEMENTED |PriceListDTO provides enabled lifecycle, priority, context and effective-window semantics.
|Multi-currency price definitions |IMPLEMENTED |Definitions carry canonical currency codes; PriceCurrencyValidationService delegates supported-code validation and authoritative minor-unit/factor resolution to Currencing public contracts, with no FX performed here.
|Effective date windows |IMPLEMENTED |Price and price-list windows use inclusive-start/exclusive-end semantics.
|Contextual price rules |IMPLEMENTED |Price- and list-level exact-match context rules support region/channel/customer-group style dimensions.
|Best-price selection |IMPLEMENTED |PriceSelectionService applies stable ranking with an id tie-break for replayability.
|Quantity/tier pricing |IMPLEMENTED |Minimum/maximum quantity invariants and tier specificity are part of selection.
|Original/reference/effective semantics |IMPLEMENTED |Selected amount is distinct from optional referenceAmountMinor metadata; no promotion semantics are embedded.
|Tax-inclusive metadata |IMPLEMENTED |Definitions preserve taxIncluded metadata while Taxating retains calculation ownership.
|Selection explanation |IMPLEMENTED |Result exposes ordered candidate ids, stable rejection reasons, explanation and price-set revision.
|History/versioning |IMPLEMENTED |Append-only Doctrine-backed PriceHistoryEntity stores canonical PriceSet revision payloads with SHA-256 integrity hashes and a unique `(priceSetId, revision)` constraint.
|Selection snapshot/provenance |IMPLEMENTED |Snapshot captures PriceSet/Price/PriceList revisions, resource reference, selection context, monetary metadata, tax flag, selected instant, and explanation for downstream persistence.
|Historical replay verification |IMPLEMENTED |PriceSelectionReplayService reruns deterministic selection against an exact historical PriceSet revision and rejects identity, revision, or monetary drift.
|Neighbor integration |IMPLEMENTED AT PRICING BOUNDARY |PriceQuoteDTO is the typed outbound Pricing contract for Cataloging/Retailing/Carting/Ordering; neighbor-specific storage/application remains owned by those repositories.
|Ecosystem adoption proof |PARTIAL |Carting already exposes a compatible typed producer-consumer seam. Cataloging still carries a legacy decimal price projection, Retailing still derives local agreed/fixed amounts, and Ordering still exposes legacy pricing calculator surfaces; their migrations belong to those owning repositories.
|===

== Milestone direction

Milestone 1: IMPLEMENTED — PriceSet/Price/value/currency/effective-window invariants.
Milestone 2: IMPLEMENTED — PriceList + contextual rules + deterministic selection result.
Milestone 3: IMPLEMENTED — quantity tiers + reference/effective + tax-inclusion metadata.
Milestone 4: IMPLEMENTED AT PRICING BOUNDARY — selection snapshot, Currencing-backed currency/precision validation, typed PriceQuoteDTO neighbor contract, durable append-only revision history, deterministic historical replay, and database uniqueness concurrency protection are implemented. Pricing owns no cache layer, so runtime cache invalidation is NOT_APPLICABLE until a cache is introduced. Cross-repository adoption remains explicitly tracked in `docs/architecture/003-ecosystem-adoption-audit.adoc`.
