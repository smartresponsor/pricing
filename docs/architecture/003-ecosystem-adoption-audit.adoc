= Pricing Ecosystem Adoption Audit
:revdate: 2026-09-21

This document verifies how neighboring repositories currently consume or project price data after Pricing introduced the canonical `PriceQuoteDTO` and provenance contracts. It records evidence only; it does not move neighbor-owned migration work into Pricing.

== Cataloging

Status: ADOPTED_WITH_LEGACY_READ_MODEL_COMPATIBILITY.

Evidence:

* Cataloging commit `9e42e087` adds `CatalogPriceableReferenceServiceInterface`/`CatalogPriceableReferenceService`, producing stable `catalog:record:<id>` Pricing-facing resource references.
* Cataloging's full test suite passes with 207 tests / 791 assertions (1 pre-existing skip); container smoke and changed-file syntax/style checks pass.
* `CatalogRecordIndexEntity` still persists a nullable decimal `price` read-model field; this remains compatibility debt and is not Pricing source of truth.

Adoption result:

* Cataloging resource identity now explicitly supplies the opaque `priceableReference` required by Pricing.
* Any retained decimal `price` field must remain a derived/legacy read-model projection rather than an authoritative reusable-price engine.

== Retailing

Status: ADOPTED_WITH_NEGOTIATED_PRICE_COMPATIBILITY.

Evidence:

* Retailing commit `4a6d2c39` adds the `pricing/price` dependency and teaches `RetailOrderIntentFactory` to consume typed `PriceQuoteDTO` facts.
* Explicit negotiated `agreedAmountMinor` retains precedence over reusable Pricing quotes; this preserves Retailing-owned agreement semantics.
* Quote identity and currency are validated against the selected retail service before an Ordering intent is emitted.
* Retailing verification passes with 47 tests / 266 assertions, PHPStan and CS GREEN; canonical gate has only repository-level coverage/UI evidence warnings unrelated to this non-UI integration.

Adoption result:

* reusable selected prices now flow through Pricing `PriceQuoteDTO`.
* negotiated vendor-response pricing remains a separate Retailing-owned commercial agreement.
* legacy local fixed-price fallback remains compatibility debt and can be retired independently without blocking the Pricing integration contract.

== Carting

Status: BOUNDARY_COMPATIBLE.

Evidence:

* `CartPriceEstimateDTO` is explicitly a typed total-price fact consumed from a pricing producer
* `CartPriceEstimateProviderInterface` is a producer-consumption seam owned by Carting
* Carting's capability audit already states that Pricing remains the price-selection owner and Carting retains its own immutable line snapshots

Required adoption:

* host integration may adapt `PriceQuoteDTO`/Pricing selection results into Carting-owned estimate and line-snapshot DTOs
* Pricing must not depend on Carting entities or mutate cart state

No Pricing repository change is required for this boundary.

== Ordering

Status: ADOPTED_WITH_LEGACY_CALCULATOR_COMPATIBILITY.

Evidence:

* Ordering commit `5a263146` persists an Ordering-owned serialization of `PriceSelectionSnapshotDTO` inside the existing `OrderPriceAuditEntity.payload` JSON field; no schema migration is required.
* Pricing provenance is now part of Ordering's canonical fast suite: 15 tests / 89 assertions; PHPStan, CS and Composer validation are GREEN.
* Ordering still exposes legacy/local pricing calculator service surfaces for existing total/tax/promotion/FX workflows.

Adoption result:

* committed orders can now retain exact Pricing selection provenance beside Ordering-owned monetary snapshots.
* legacy calculator retirement/narrowing is compatibility cleanup, not a missing Pricing integration seam.
* tax, promotion, FX, payment, shipping and order-total ownership remain outside Pricing.

== Cross-component conclusion

The required cross-component Pricing integration seams are now implemented: Cataloging supplies stable priceable references, Retailing consumes typed Pricing quotes, Carting already exposes a compatible typed producer-consumer seam, and Ordering persists selected-price provenance.

Remaining decimal/fixed/calculator paths are explicitly legacy compatibility surfaces in their owning repositories. Their later retirement must remain owner-local and does not require expanding Pricing ownership.
