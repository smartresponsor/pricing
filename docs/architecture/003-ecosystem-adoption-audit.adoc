= Pricing Ecosystem Adoption Audit
:revdate: 2026-09-21

This document verifies how neighboring repositories currently consume or project price data after Pricing introduced the canonical `PriceQuoteDTO` and provenance contracts. It records evidence only; it does not move neighbor-owned migration work into Pricing.

== Cataloging

Status: MIGRATION_REQUIRED_AT_CATALOGING_BOUNDARY.

Evidence:

* `CatalogRecordIndexEntity` still persists a nullable decimal `price` field and exposes it as float.
* Cataloging's own capability audit states that Pricing remains an external reference and must not become an embedded engine.

Required adoption:

* keep Cataloging resource identity as the source of the opaque `priceableReference`
* replace authoritative local price semantics with a Pricing-derived projection/reference where commercial price is required
* retain any denormalized price only as an explicitly derived read-model field, never as Pricing source of truth

== Retailing

Status: MIGRATION_REQUIRED_AT_RETAILING_BOUNDARY.

Evidence:

* `RetailOrderIntentFactory` accepts `agreedAmountMinor`, reads local selection/pricing profiles, and formats the amount into an Ordering intent
* Retailing's capability audit marks Price reference as PARTIAL and explicitly says to reference Pricing results rather than calculate prices locally

Required adoption:

* consume `PriceQuoteDTO` for reusable selected-price facts
* preserve separately negotiated/agreed vendor-response pricing as Retailing-owned commercial agreement where it is not a reusable catalog price
* stop treating local fixed pricing profiles as an alternative reusable-price engine when Pricing can provide the selected price

== Carting

Status: BOUNDARY_COMPATIBLE.

Evidence:

* `CartPriceEstimateDTO` is explicitly a typed total-price fact consumed from a pricing producer
* `CartPriceEstimateProviderInterface` is a producer-consumption seam owned by Carting
* Carting's capability audit already states that Pricing remains the price-selection owner and Carting retains its own immutable line snapshots

Required adoption:

* host integration may adapt `PriceQuoteDTO`/Pricing selection results into Carting-owned estimate and line-snapshot DTOs
* Pricing must not depend on Carting entities or mutate cart state

No Pricing repository change is required for this boundary.

== Ordering

Status: MIGRATION_REQUIRED_AT_ORDERING_BOUNDARY.

Evidence:

* Ordering owns committed monetary snapshots and an `OrderPriceAuditEntity`
* Ordering still exposes legacy/local pricing calculator service surfaces
* Ordering's capability audit correctly states that committed order owns snapshots, not upstream calculation engines

Required adoption:

* persist Pricing `PriceSelectionSnapshotDTO` provenance (or an Ordering-owned serialization of the same facts) beside committed selected prices
* preserve Ordering total/snapshot ownership
* retire or narrow local reusable-price selection/calculation paths that duplicate Pricing ownership
* continue keeping tax, promotion, FX, payment, and shipping execution in their owning components

== Cross-component conclusion

Pricing now exposes the required canonical producer-side contracts. Remaining code migrations are intentionally located in Cataloging, Retailing, and Ordering; Carting already exposes a compatible producer-consumer seam.

Those migrations must be executed in the owning repositories so their own Canonization, persistence migrations, tests, and release gates remain authoritative. Cross-repository writes from Pricing would violate component ownership.
